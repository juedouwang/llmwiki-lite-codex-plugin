# 科研工作台：先把主要功能做出来

> 版本：精简执行版 v1.1 · 2026-09-19。状态：实施范围调整，尚不代表功能已完成。
> 本文只调整计划，不授权现在修改功能、启用采集、创建定时任务或提交代码。
> 在本仓库后续实施中，以本文决定先做什么；上一版完整执行规格不再作为首版的全量交付门槛。

## 1. 纠正上一版的方向

主要矛盾不是缺少复杂架构，而是：**日常工作没有顺手、连续地留下记录，第二天难接着做，周末难整理周报。**

第一条链路应当是：

**正常科研 → 记录对话、笔记和改动 → 知道上次做到哪 → 自动形成日报 → 整理周报并保存提交版。**

Git、文献库和知识库是用户明确要求的核心功能，也要做，但先交付它们最常用、可实际操作的部分，不先造一个完整通用平台。

执行原则：

- 沿用现有简约界面、笔记、进度、项目注册和 Markdown，不再次重构全站。
- 明确用户能做什么、点击后发生什么；不预先冻结几十个模块、所有字段和所有未来异常。
- 一次做通一条真实流程再扩展，不要求所有模块同时完成才可使用。
- 已有实现能用就复用；工作区存在的在途代码不自动删除，也不因它已写出就扩大交付范围。
- 不为未来多人并发、海量数据、所有 Git 场景建设基础设施；现阶段服务本机单用户科研。

## 2. 核心功能保留到什么程度

| 功能 | 首版必须能用 | 暂时不做 |
| --- | --- | --- |
| 多项目与进度 | 切换项目；已有任务时间轴；上次做到哪、下一步；首页看到各项目最近进行中的任务 | 自动拆任务、依赖网络、自动预测完成率、资源排程 |
| 手动笔记 | 直接输入、Ctrl+V 截图、批注、自动保存；时间在笔记信息里查 | 再造编辑器、复杂块插件、多人协作 |
| 工作留痕 | 明确项目的助手对话、手动笔记、任务变化、文件改动摘要和提交记录 | 全账户历史回溯、所有工具一次接完、完整终端日志归档 |
| 日报与周报 | 定时日报、周报草稿；可修改、可复制/下载；提交版保留；周报可选择多个项目 | 自动发导师、邮件、PPT/DOCX、复杂审批和版本分支 |
| 文献库 | 只放文献；粘贴地址可收藏；助手提到的明确论文可收录；原文和阅读笔记可选 | 自动全盘搜索 PDF、强制下载、复杂推荐系统、批量元数据治理 |
| 知识库 | 与日报共用当天材料自动整理；新增自动写入；修改旧内容或冲突时确认 | 每次文件保存就推理、所有提交都即时重建、知识图谱和推理框架 |
| 可视化 Git | 分支图、节点详情、修改查看、选择文件提交、建/切分支、合并、恢复旧版本、拉取和推送 | 从网站新建/克隆仓库、高级 reset/rebase/cherry-pick、强推、行级暂存、多 worktree/LFS/子模块写操作 |

“暂时不做”不能偷偷成为其他功能的前置依赖。未支持的少见操作明确说明即可，不为它提前开发通用恢复系统。

## 3. 开发顺序：六项就够

### M-01：把已经有的记录和进度用顺

**工作**：检查现有笔记和时间轴，修实际阻碍操作的问题，不换技术栈、不重做视觉。

固定交互：

- 正文区域粘贴截图直接进入笔记；标题、批注等输入框仍保持正常粘贴行为。
- 新文字块直接输入；常用操作无需反复打开菜单；不要给每块常驻一排图标。
- 笔记时间留在“笔记信息”，不插到正文。
- 项目首页显示最近进行中的任务及“上次做到哪 / 下一步”；点击即可回到对应任务或笔记。
- 阶段成果先用现有笔记记录图片、指标和说明，任务可以关联该笔记，不建立新的实验数据库。

**完成标准**：截图、写两句说明、关联任务、关闭后再打开，内容与停止点都在。已有能力通过即可，不为“完成任务”重写它。

### M-02：先把一个项目的一天收集完整

**依赖**：M-01 的笔记/任务入口可读；不依赖 Git 可视化完成。

先接通当前主用的 Codex 项目会话；Claude Code、OpenCode 在 M-06 复用这条流程接入。

材料仅分四类：授权的用户/助手对话、科研笔记、任务变更、文件改动/提交摘要。每条保留项目、时间、来源、内容或引用即可，不先建设复杂证据体系。

- 第一次明确选择项目与会话读取范围；不扫描整个账户，不接 ChatGPT 网页端。网页聊天继续手动记笔记。
- Hook 只通知“这里有新活动”，不负责总结、不启动模型。对话正文由该宿主实际可用的读取方式补齐；不能把路径变化当成已经收集了对话。
- 同一消息或同一文件快照重复检查不重复入库；排除密钥、依赖目录和本工具生成的报告，避免收集自己生成的内容。
- 先用一天真实工作的样本核对：能说清楚做过什么，也能说清楚哪些内容没有覆盖。
- 在这一步尽早验证无窗口定时执行是否能读取项目材料并写回一份测试结果。测试需明确授权，不能等界面全部完成才发现无法自动运行。

**完成标准**：正常完成一次讨论、修改文件、记笔记后，在同一项目下找到对应活动；重复读取不增加重复项，别的项目不混进来。

### M-03：日报、周报和知识维护共用一次整理

**依赖**：M-02。有材料以后立刻验证报告质量，不先做通用任务调度平台。

处理顺序固定：**收集未处理材料 → 整理文献候选和知识增量 → 写日报 → 到周报时间时汇总周报。** M-04 接通前文献候选可以保留，不阻塞日报。

实现过程中先手动运行一次以验证质量，再接定时；手动运行不是最终交付，定时运行才算本项完成。网页不创建新的聊天系统，由获授权助手做整理。

报告与留痕：

- 日报按项目和自然日保存；固定四部分：“今天做了什么 / 结果与发现 / 问题 / 下次从哪继续”，底部列关键来源。
- 周报按周一到周日归属，按研究目标整合而非拼接日报；固定“本周进展 / 结果 / 问题 / 下周计划”，可选择多个已授权项目。
- 不把讨论写成已完成，不把代码提交写成实验成功；无材料写“无可用记录”，不推断没有工作。
- 默认建议日报 22:00、周报周五 18:00，时区 Asia/Shanghai；用户启用时确认，不提前自动设置。周五的是截至当时的草稿，不能声称已覆盖周末。
- “确认提交版”保存独立的 Markdown 副本；之后只改草稿，不覆盖已提交文件。先保留简单的草稿/提交版，不开发复杂版本链。
- 自动重跑可以更新未被人工编辑的草稿；人工改过就保留原稿，把新结果作为待采用草稿。周末新增工作进入原周期的补充草稿。

知识维护：

- 初版每天跟日报一起整理；保留“立即整理”入口，不同时做实时监听和每次提交即时推理。
- 有来源的新增内容正常自动补充；需要改写旧段落、删除或新旧结论冲突时进入“待确认”。
- 不主动弹窗打断工作；点击待确认项再显示旧内容、建议和“保留 / 采用”按钮。无法判断时不覆盖。
- 不要求总结前先清空所有知识冲突，日报标明争议即可。

自动运行：

- 只使用一个已验证、获授权的无窗口运行入口，按已设定时间检查到期任务；不重新引入后台循环 `codex exec`。
- 电脑或执行端未运行就显示未生成，下次运行补最近缺失日报和当前待生成周报；不设计多执行器、分布式租约和任意历史重放。
- 只需简单的待处理/处理中/完成/失败记录和“重试”入口。一次串行处理；同项目同日期不重复出日报。
- 若自动执行不可用，明确把本项标为“自动运行未完成”，其他可用功能仍可交付，不假装已经定时生成。

**完成标准**：真实连续使用后，日报能解释一天的工作；周报能从这些材料生成；人工编辑和提交版不会被下一次自动整理覆盖；全程无终端弹窗。

### M-04：文献库只收文献，先把收藏做好

**依赖**：现有文献页面；自动收录复用 M-02/M-03。

- 手动添加只要求标题和网址，DOI/arXiv 可以作为地址；作者、年份、PDF、阅读笔记都不是入库前置条件。
- 已授权对话明确提到论文并有可定位地址/标识时可以自动收录；只提模糊名字且无法确认时留为候选，不编造论文或网址。
- DOI/arXiv/规范化地址相同则补来源，不重复增加；单凭同名不自动合并。
- 列表只有论文等文献条目，不因为项目里出现 PDF 就自动展示。历史混入的文件从列表排除，不删除源文件。
- 点击条目查看地址、已有原文、阅读笔记和讨论来源；不下载也能一直收藏。

**完成标准**：一篇只有链接的论文能收藏、重启后能找到；重复提到不重复入库；依赖包 PDF 和实验报告不混入列表。

### M-05：交付真正能点的 Git，不做完整 Git 客户端

**依赖**：现有项目绑定。可以独立推进，但不把复杂 Git 后端作为日报留痕的前置条件。

先支持普通单工作树仓库，每项目绑定一个仓库，复用已有 Git 模块中实际可用的部分。

固定页面：分支列表、提交图、节点详情/文件修改。图按父子关系绘制；节点点击展开，不堆独立仪表盘和多余动画。

首版按钮及行为：

| 操作 | 点击后做什么 |
| --- | --- |
| 查看节点 | 显示提交说明、修改文件及差异 |
| 保存版本 | 用户选择要提交的文件，填写说明后提交；不自动上传 |
| 创建/切换分支 | 从选定节点创建分支或切换已有分支；有未提交修改就先提示提交/自行处理 |
| 合并分支 | 选来源、确认合入当前分支；普通文本冲突可选保留哪边或编辑，处理后继续，也能取消 |
| 恢复到此版本 | 先显示影响，再用当前分支的新提交恢复旧代码状态，保留后续历史；不使用 hard reset 冒充恢复 |
| 获取远端/上传 | 用户选明确远端；拉取可快进则更新、分叉则进入合并；上传只做普通 push |

合并、切分支和恢复要求工作区/index 干净；不干净就停止并说明，不先实现自动 stash、任意现场快照或恢复引擎。二进制/重命名等首版未覆盖冲突清楚提示用户在本地处理，不能宣称全部冲突可网页解决。

**完成标准**：在测试仓库不用终端完成“提交 → 建分支 → 合并 → 恢复旧版本”，并能看到真实分支和历史；恢复后原提交仍存在。不是只有分支图能看。

### M-06：接其他助手，再做一次整体使用验收

**依赖**：M-02/M-03 主流程已可用；整体验收还需 M-04/M-05。

- 给 Claude Code、OpenCode 分别接消息来源，不重做日报、知识维护和存储。每接一个，用真实对话验证一次，不要求三个宿主同时开发完才试用。
- 对话各自标明来源和项目；不靠模型猜测跨项目归属。未接入的会话明示未覆盖。
- 跨项目首页只显示当前任务/下一步；跨项目周报复用现有项目材料，不另做管理驾驶舱。
- 按下面八条验证；发现日常使用问题优先修，不在此时追加后续功能。

**完成标准**：三个本地助手各有可验证的接入样本；真实科研连续使用三天；能从项目任务找到记录，从周报找到依据。

## 4. 工程上只保留必要底线

不是取消保护，而是不开发用户还用不到的保护框架。保留四条即可：

1. 不覆盖人工笔记/人工报告，不删除源论文，不静默改写旧知识。
2. Git 可能覆盖内容的动作先确认；脏工作区先停止，不自动强推或丢弃修改。
3. 只读取获授权项目/会话；沿用已有本地服务与路径限制，不扩大成全盘采集。
4. 后台不弹终端；失败可见、有重试，不把失败显示成成功。

优先复用现有原子保存、修订校验、Markdown 和简单索引。有已写好的 SQLite 模块可以按实际需要复用，但不要求先完成十张表才能写第一份日报；不新增通用队列、插件框架、完整迁移回滚平台或多层领域模型。

## 5. 首版只验收八件事

| 编号 | 用户实际验证 |
| --- | --- |
| A-01 | Ctrl+V 截图、批注、保存、重新打开都顺手；时间不占正文 |
| A-02 | 次日打开项目，知道上次做到哪、下一步做什么；能找到成果笔记 |
| A-03 | 一次助手讨论、文件修改、笔记和任务变化都有来源，重复采集不重复、项目不串 |
| A-04 | 定时生成日报，内容符合当天实际工作；缺少来源明确说明、后台不弹窗 |
| A-05 | 周报可汇总所选项目、修改、导出、保留提交版；自动再生成不覆盖人工内容 |
| A-06 | 新知识自动补充，改旧结论须确认；未解决冲突不阻塞整份日报 |
| A-07 | 纯链接文献能收藏，助手提到的明确论文能收录，不混入无关文件 |
| A-08 | Git 图可交互，真实完成提交、分支、合并、恢复和普通远端操作 |

八条是用户验收目标，不是限制必要单元测试的数量。每项检查最常用的成功路径和直接影响内容安全的失败路径，不把全部罕见故障排列组合变成首版门槛。功能未通过就如实记未完成，不用“架构已完成”替代“用户能用”。

## 6. 明确后置，不在实施时顺手添加

- 云端部署、远程全天运行、多用户和权限体系。
- Git 高级操作、所有特殊仓库、任意脏现场自动恢复、复杂图谱布局优化。
- 全历史对话回填、任意第三方助手、ChatGPT 网页自动采集。
- 知识实时推理、每次 Git 提交即时维护、语义搜索平台和知识图谱。
- 独立实验管理库、自动生成幻灯片、报告投递和复杂审批链。
- 为未来规模设计的分布式作业、完整事件重放、全局事务和迁移框架。

首版完成后，根据真实使用遇到的问题再选下一项，不按上一版长清单继续自动扩张。

## 7. 与旧规格和当前代码的关系

- 上一版 23 项任务、91 项场景可作为遇到问题时的参考，不再要求全部实现。任务执行和完成标准改用 M-01～M-06 / A-01～A-08。
- 当前主仓库没有上一版原文件；检查时在 bigchange、claude、opencode 三份工作副本发现同内容的规格。此次不改动那些副本和在途功能代码。
- 本文件是主仓库的精简入口。其他工作副本开始或继续实施前也应明确采用此范围，不能一边按精简版，一边继续实现旧版全部基础设施。
- 不为切换计划而删除已有代码、重置仓库或迁移用户数据。只保留能服务当前六项任务的开发工作，其他工作停止扩展。
