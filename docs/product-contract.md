# LLM Wiki Lite 产品原则

本文只保留跨功能的稳定原则，不是版本发布说明或第二套实施规格。功能行为、界面和验收以[文档入口](research-workbench-handoff.md)指向的 OpenSpec 为准；安装、发布与实现规范分别看仓库 README、RELEASING 和 AGENTS。

## 产品宗旨：简单、优雅、好用

- **简单**：围绕真实科研操作，减少步骤、入口和重复信息；不增加无必要的功能或配置。
- **优雅**：视觉克制、交互一致，反馈及时；不靠多余装饰或动画掩盖等待。
- **好用**：优先保证常用操作顺手、页面响应流畅、数据可靠；性能优化以实际测量和使用感受验收，不只看接口成功。

## 1. 产品定位与职责

面向个人、多项目科研工作的本地工作台；助手负责理解与整理，网页负责查看、记录、编辑、确认和明确授权的操作。复用现有简约界面，不重建聊天系统或庞大的管理平台。

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| Skill / 宿主 LLM | 阅读必要来源、理解、核验和写作 | 区分事实、推断、未验证；不凭文件变化认定科研成功 |
| MCP / 确定性程序 | 注册、读取、检索、快照、存储和状态管理 | 不替代科研推理，不自行臆造结论 |
| Hook | 提供可能变化的路径提示 | fail-open；不阻塞工作、不启动模型、不自行改写知识 |
| Web | 项目浏览、记录编辑、结果展示和确认操作 | 不是独立知识引擎；不自建模型服务 |

## 2. 记录和知识不混为一谈

- Todo / Done / 继续上次：维护任务、排期、精简完成事项和停止点；任务名称、计划日期和完成状态由用户控制。
- 日报 / 周报：可追溯的过程与汇报文档；用户明确确认后才形成正式版本，自动保存不等于确认。
- 知识库：项目架构、术语、方法和长期理解；优先少量有来源的 Markdown，不固定十五类页面、不生成空模板。
- 文献库与阅读笔记区分原文事实、助手解释和待验证推断；精确公式、数值和引用回到原文核验，不把笔记伪装成原文。

以上只说明职责；具体编辑、生成、保护和确认流程只在对应功能 spec 中维护。

## 3. 项目与数据边界

- 每项目区分 `source_root`（真实项目）、`wiki_root`（人类可读内容）、`state_root`（机器状态）；注册不代表已扫描、理解或启用自动整理。
- 未配置全局位置时 Wiki 默认在 `<project-root>/wiki`；配置外部根目录时各项目分开，不能跨项目混写。
- 存储迁移默认复制，非空目标不静默合并覆盖；迁移、取消注册不自动删除旧文件。
- Markdown 保持可直接阅读；中文优先，代码、API、精度敏感术语和论文标题保留必要原文。
- 时间、来源和历史能查询，但不把系统元数据插入正文或常驻占用主要界面。
- 人工内容和正式版本不被自动结果覆盖；原论文不因整理被修改或删除。知识新增与修改旧内容区别处理，具体规则见知识维护 spec。

## 4. 低打扰与真实性

- 前台操作不等待 AI 总结；增量处理有变化的材料，不每次重扫、重写全部内容。
- 只读取获授权项目/会话；材料不全就说明覆盖缺口，不宣称掌握所有助手对话。
- 不重新启用后台循环 `codex exec` 或弹终端的后台程序；实际自动运行端和任务启用需明确授权。
- 失败、未接通、尚未验证如实显示；接口/mock/手工测试成功不等于自动化已完成，计划写好不等于代码已实现。
- 不为未来规模建设通用框架；优先复用已有能力，但不能用“简约”作静默覆盖或丢失数据的理由。

## 5. 本地服务与必要保护

- 当前网站只绑定回环地址；云端/跨用户部署不属于当前范围。
- 文件操作限定在对应注册根目录；校验路径、附件类型和大小，拒绝越界与不安全的符号链接访问。Wiki 内容及附件保存在对应 Wiki 根目录。
- 源论文只读；源 HTML 不在站内执行，Markdown/粘贴内容不执行注入脚本。网页不因渲染内容而自行加载不可信远端资源。
- 写入沿用必要的原子保存和冲突检测；有风险的用户操作要说明影响并确认，不把保护扩展成通用恢复平台。
- 沿用现有轻量技术栈和本地资源；不因旧文档写过某个目录、字段或组件就将其当作新功能的强制依赖。
