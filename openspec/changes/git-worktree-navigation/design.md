## Context
沿用现有 Git 预览确认、common-dir 锁、纯 SSR 页面壳和带 query 的缓存导航。

## Goals / Non-Goals
仅在同项目管理已有工作树。无自动合并、新建或移除工作树，无新增项目，无后台任务。

## Decisions
- URL 使用 `?worktree=<opaque-id>`。ID 绑定 home、项目、注册根目录、common-dir 和工作树路径；后端每次从注册仓库 worktree list 重新定位，不能接受客户端路径。
- GET/POST 均通过 query 传递上下文，不混进严格业务 payload。选中目录核验 top-level/common-dir/双向 Git 绑定，执行前锁内重建同一上下文。
- 默认注册目录仍用原状态路径；其余目录状态存于 git-web/worktrees/<id>，预览与文件 ID 保留目录绑定。锁仍使用共享 common-dir。
- 菜单列目录名、分支和完整路径；链接复用现有导航和草稿保护。切到其他栏目再点击默认代码入口返回注册目录；历史记录与直接刷新保留工作树 URL。不做全局隐式选择。
- 列举其他工作树只读登记和绑定文件，不扫描其 dirty/index；单工作树菜单隐藏，保持原型布局。

## Risks / Trade-offs
- 工作树可被外部移动 → 每请求校验，失效时报错并提供返回注册目录；不自动转向写入。
- 多目录共享分支和配置 → 保留共享锁和原有保护；说明切分支与进入目录不同。
- 正在自托管的代码服务不热加载后端 → 临时服务完成验收，部署需重启原服务，不绕过已有停止策略限制。

## Migration Plan
不迁移注册表或研究数据。更新源码后重启服务；回退此提交即可撤销入口，原目录状态格式不变。
