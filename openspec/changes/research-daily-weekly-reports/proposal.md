## Why

科研任务跨天推进，用户需要自动形成可追溯的详细日报，再提炼成可提交的个人周报；网站必须能直接改稿和确认，不能依赖聊天或逐个添加 block。现有科研记录已有 Markdown 渲染、截图上传和保存能力，应复用而非引入另一套复杂编辑器。

## What Changes

- “日报与周报”改为独立一级栏目，与“科研记录”分开；两者复用连续 Markdown 编辑/预览交互。科研记录新建直接聚焦正文，不显示图片按钮、不要求添加 block，Ctrl+V 直接插入截图。
- 日报按北京时间自然日汇总全部已选项目，一天只有一篇；个人周报从这些多项目日报提炼，一周只有一篇。两者独立保存于工作台，不归档到任何科研项目。日报不规定章节，周报严格采用用户的刘亚宁周报模板。
- 自动保存只保存草稿；明确确认才产生正式版本。人工改稿、正式版和新的 AI 候选互不覆盖，时间、来源和历史藏在详情中。
- 用户已选择 Codex 内置计划任务作为本期执行端。设置时选择取材项目和时间，不选择归档项目；定时任务调用插件确定性工具取材、由宿主 AI 总结、再保存。睡眠后补齐、去重和错误反馈由本规格明确约束。
- 资料来源限已有项目科研记录、手动笔记、任务历史、Git 只读材料和已授权采集材料。对话适配器缺失时如实披露缺口，不冒充掌握全部聊天。
- 不新增运行时依赖、云服务、自建调度进程或后台 `codex exec`，不批量迁移历史 block 笔记，不变更 Todo/Done 或知识维护语义。既有业务先保留，再完成已确认整站原型的共享壳与连续笔记接入。

### 2026-09-20 已确认界面对齐增量

以 `design.md` D-11 指定的整站 HTML 源稿为界面依据，D-12 固定连续笔记的兼容方案。复用现有实现、保留旧 API/数据/验收证据；原勾选任务是之前业务阶段的结果，新界面任务单独未勾选。此修订只更新规划，不表示已经改造真实网站或启用了自动化。
