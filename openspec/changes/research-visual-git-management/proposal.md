## Why

科研人员需要在项目网页内看懂版本、保存工作、尝试分支并安全合并或恢复，而不是只看一张提交图后回到终端操作。用户已于 2026-09-19 确认交互示意；本 change 将其固定为第五份可交付、可验收的执行规格，不继续扩展成完整 Git 平台。

## What Changes

- 沿用项目 `/code` 入口，名称由“代码图谱”调整为“代码”；采用已确认整站原型中的代码栏目：分支工具条、未保存修改、提交关系图、可收起的版本详情；共享壳只引用第二份 design D-11。
- 完整交付“选文件保存本地版本 → 从节点建分支 → 切换分支 → 合并 → 解决普通文本冲突或取消 → 恢复旧代码并生成新提交”。保存不等于上传，恢复不删除历史。
- 提供明确目标的拉取和普通上传。分叉拉取复用合并流程；不偷偷 stash、不 rebase、不强推、不弹出终端或认证窗口。
- 保留已有 Git 底层能力，补齐网页连接、真实差异、选中文件提交和必要状态复核；已有模块存在不等于其行为已经满足本规格。
- 提交及合并只形成 Git 事实，不自动完成 Todo、不即时生成日报或修改知识。前三份已有采集/每日整理机制继续独立工作。

## Capabilities

### New Capabilities

- `research-visual-git`: 项目内的可交互版本图、完整文件提交、分支操作、合并冲突处理、保留历史的恢复、显式远端同步与低打扰反馈。

### Modified Capabilities

无。当前没有已归档主规格；第一至第四份 change 的功能和自动任务边界不变。

## Impact

- 页面：现有共享导航和 `/project/<id>/code` 页面；局部新增代码管理样式/脚本，接入第二份已经统一的共享壳，不重复重构网站。
- 后端：现有 `git_service.py`、`git_graph.py`、`git_operations.py`、`git_merge.py`、`git_revert_restore.py` 及网页路由；加一个薄的网页请求适配模块，不重建 Git 库。
- 数据：真实 Git 仓库仍是真相来源；仅在已注册 `state_root` 下保存必要的短期操作状态，不把机器日志放进知识正文。
- 依赖：Python 标准库、现有本地前端资源、已安装 Git；不增加框架、数据库、后台模型或调度器。
- 测试：临时普通仓库、临时 bare 远端和浏览器真实点击流程。实际 GitHub 凭据/仓库验证另外授权，不能把本地远端测试说成已经联通 GitHub。

## Non-goals

首版不做仓库新建/克隆、分支/标签/远端的综合管理、行级暂存、amend/reset/rebase/cherry-pick、强推、多 worktree/LFS/子模块写操作、通用灾难恢复、AI 提交说明或独立 Git 后台。已有高级代码既不自动开放，也不顺手大规模删除。此轮仅写规划材料，不改业务代码、不操作真实科研仓库。
