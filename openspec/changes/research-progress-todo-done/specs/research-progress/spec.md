# 第一份：科研进度、Todo / Done 与“继续上次”

> 2026-09-19 · 待审核的执行规格。本文是本功能唯一的用户行为依据；技术方案与任务清单不得扩展它。本轮不实施。
> 已确认：用户控制任务/日期/状态；助手整理上下文；人工内容不被覆盖；前台不等待总结；Todo/Done、日报、知识库分开。
> 本文中的显示数量、排序、刷新间隔等是提交你审核的具体设计，不冒充你此前逐项确认过。

## Purpose

让科研人员在多个项目之间切换、跨天继续未完成任务，并保留简短的已完成事项及其材料。继续上次是同一套任务的恢复入口，而非独立摘要系统；详细工作过程留给日报，项目架构与知识理解留给已有 LLM Wiki。

## ADDED Requirements

### Requirement: P-01 只完善任务功能且诚实区分自动能力

系统 SHALL 保留现有简约界面和任务时间轴。本次只交付任务管理、完成留痕、上下文的接收/保存/展示；不实施日报、周报、知识整理、对话采集或无人值守模型运行。实际自动生成尚未接通时 MUST 明确说明，不能用测试摘要冒充自动化完成。

#### Scenario: A-01 没有自动执行端时仍然可用
- **WHEN** 用户尚未接入自动生成来源，打开任务详情
- **THEN** 仍可创建、编辑、完成任务和手写上下文；“自动整理”详情说明“自动整理尚未接通”；不弹窗、不启动模型或终端，也不显示虚假的“正在整理”。

### Requirement: P-02 Todo 跨天保留且由用户控制

系统 SHALL 使用原有四种状态：未开始、进行中、卡住了、已完成。前三种属于 Todo；默认新任务为未开始，无排期。标题必填，最多 240 字符；日期要么都空，要么都有且结束不早于开始。状态不因午夜、文件变化、对话建议或 Git 提交而自动变化。

#### Scenario: A-02 快速新增与跨天继续
- **WHEN** 用户输入“验证夜间数据”并回车，随后将状态切为进行中，次日重新打开
- **THEN** 同一个任务 ID、标题、状态和已有内容仍保留，不复制为“今天的新任务”，不自动顺延日期；空标题或无效日期就地提示且不丢输入。

#### Scenario: A-03 修改文件不等于完成任务
- **WHEN** 助手收到新的对话或文件变化，其中包含“建议完成验证”
- **THEN** 不能创建任务、改标题、改排期或改完成状态；只能向已有明确关联的任务提交自动上下文。

### Requirement: P-03 Done 留存、完成时间及重新打开

系统 SHALL 将用户明确标记完成的任务移入默认折叠的“已完成（数量）”，保留原 ID、标题、材料与上下文。列表只展示精简任务行，不塞入日报正文；真实完成时间在“任务信息”中查询。修改已完成任务的标题不能改变其完成时间。用户通过同一状态选择器重新打开任务，后续再次完成使用新的实际完成时间，之前的完成事实保留在现有修改记录中。

#### Scenario: A-04 完成与重开
- **WHEN** 用户把进行中任务标记为已完成，再切回进行中，最后再次标记已完成
- **THEN** 它依次离开 Todo、回到 Todo、再次进入 Done；始终只有一个任务；第一次与第二次完成动作可在修改记录中区分，重开期间不把它当作当前已完成事项。

#### Scenario: A-05 旧 Done 不伪造完成时间
- **WHEN** 已有或导入的完成任务没有可靠完成时间
- **THEN** 保留完成状态，任务信息显示“完成时间未记录”；不得用文件修改时间、迁移时间或当天日期冒充。

### Requirement: P-04 页面结构与继续上次的确定规则

系统 SHALL 使用以下布局与规则，不新增看板、单独的交接页或百分比仪表盘：

| 位置 | 固定行为 |
| --- | --- |
| 项目列表 | 保留项目列表；有进行中/卡住任务时附一行最近任务标题，可直达该任务。没有时只显示原项目条目。 |
| 项目入口 | 从项目总览进入科研进度；旧项目根 URL 仍可打开知识库，但不再在知识阅读区重复放任务摘要。 |
| 科研进度页 | 按确认原型：顶部新建任务、单张“继续上次”、周时间轴、未排期、折叠 Done；新建打开轻量任务表单，不常驻重复表单。 |
| 继续上次 | 只选进行中/卡住任务，按用户最后修改时间降序，同一时间按任务 ID 升序；显示排序第一项的标题、状态、上次做到哪、下一步及可用关联笔记入口，其余任务仍在时间轴/未排期中可达。自动摘要不重新排序。 |
| 时间轴 | 只画用户填写的计划日期；无日期放未排期；Done 不重复画在未完成时间轴。默认本周一至周日，上一周/本周/下一周切换；原两周/四周能力收在次要范围菜单，不新增拖拽排程。 |
| Done | 已知完成时间按最近完成优先；时间未知放末尾；相同时间按任务 ID 升序。 |
| 任务详情 | 编辑名称/状态/日期/两段上下文/一篇关联笔记；时间、来源及修改记录折叠查询。 |

上下文预览每段最多两行，完整内容在详情中。空值显示“暂无记录”，不催促用户每日手填。没有进行中/卡住任务时隐藏继续上次，未开始任务仍在 Todo。

#### Scenario: A-06 多项目与精简入口
- **WHEN** 项目 A 有四个进行中任务，项目 B 只有未开始任务，用户从项目列表进入 A
- **THEN** A 的列表摘要和科研进度中的继续上次指向排序第一的任务，其余任务仍可从时间轴/未排期打开；B 不借用 A 的上下文，也不把未开始任务伪装成“上次正在做”。

### Requirement: P-05 人工与自动上下文按字段分开

系统 SHALL 分别保存人工和自动的“上次做到哪”“下一步”。每个字段独立采用“人工优先，否则自动”；用户明确清空也属于人工修改，不能被自动填回。进入详情或只改标题不应把自动内容变成人工覆盖。每个字段最多 4000 字符。

详情默认显示有效内容。存在人工覆盖时，提供就地的“使用自动内容”操作，并在默认折叠的“自动整理”中保留最新自动版本；点击该操作才解除对应字段的人工覆盖，另一个字段不受影响。自动版本的更新绝不修改任务状态。

#### Scenario: A-07 手改与自动更新并存
- **WHEN** 用户只手改“下一步”，新的自动上下文到达
- **THEN** “上次做到哪”显示新自动内容，“下一步”仍显示用户版本；展开自动整理能看到新的自动建议及来源。

#### Scenario: A-08 清空与恢复自动
- **WHEN** 用户把“下一步”清空并保存，随后收到自动更新，再主动点击该字段的“使用自动内容”并保存
- **THEN** 自动更新到达时仍为空；只有最后的明确操作才改用最新自动版本。只打开详情或修改标题不得切换字段归属。

### Requirement: P-06 接入结果可追溯且不猜关联

系统 SHALL 仅接受明确指定项目和已有任务、并引用该项目已保存科研记录的自动上下文。来源关联由调用者明确提供，不用标题相似度猜任务。来源记录与用户选择的“关联笔记”分别保留；接入操作不能修改标题、日期、状态或人工字段。重复提交同一结果不重复写入、不刷新生成时间；旧版本提交不得覆盖较新结果。

#### Scenario: A-09 合法结果与越权结果
- **WHEN** 调用者向任务 A 提交两段摘要及 A 所属项目中的有效记录来源
- **THEN** 只更新任务 A 的自动上下文，详情可以打开原记录；若任务/来源不存在、越出项目，或携带改状态等未允许字段，则明确拒绝且原内容不变。

#### Scenario: A-10 重复提交和旧结果
- **WHEN** 同一摘要重复送达，或较旧的处理结果在新版本保存后才到达
- **THEN** 前者不新增重复数据，后者报告版本冲突且保留新版本；不强制用户处理后台摘要冲突，不无限自动重试。

### Requirement: P-07 材料关联不复制或改写原文

系统 SHALL 复用现有“一项任务关联一篇科研记录”的能力；手动笔记和助手记录均可选择、打开、更换或取消关联。任务只保存引用，不把截图、笔记正文或日报复制进任务行。来源消失时只提示，不删除任务、不擅自清空引用。

#### Scenario: A-11 材料与旧记录保持原样
- **WHEN** 用户关联一篇含截图的笔记，之后取消关联，或原记录在外部被移走
- **THEN** 前者不改动笔记及图片，后者在详情提示“来源不可用”且保留任务；旧科研日档的候选导入仍需用户选择，不重写日档。

### Requirement: P-08 生成与前台解耦且更新不抢输入

系统 SHALL 在页面打开、任务保存、笔记保存、Hook 与 Git 操作的前台链路中不触发或等待 AI 总结。读取任务摘要不得扫描项目代码或全部科研记录；笔记选择与旧候选仅按需加载。当前项目页面可见时每 5 秒轻量读取已保存结果，同一页面最多一个在途刷新请求，隐藏时暂停，重新可见时读取一次；该刷新不触发生成。

新结果就地替换非编辑状态下的自动展示，不刷新整页、不关闭详情、不移动焦点、不覆盖未保存输入。后台失败保留上次成功内容，以非弹窗状态提示；没有接入来源不能假装已在后台重试。

#### Scenario: A-12 慢生成不拖住正常操作
- **WHEN** 测试接入端被人为延迟 30 秒或不可用，用户创建任务、切换状态、打开笔记、返回项目页
- **THEN** 操作无需等待该端，旧上下文仍可读；无整页遮罩、弹出终端、独立模型调用或因生成未完成而禁用按钮。保存本身仍需正常的本地落盘确认。

#### Scenario: A-13 页面更新与正在编辑的内容
- **WHEN** 用户正在输入下一步，后台保存了新摘要
- **THEN** 下一次成功轻量刷新后更新未编辑的摘要显示，但不改当前表单及光标；关闭/保存后重新打开详情可读取新版本；隐藏标签页不持续轮询。

### Requirement: P-09 旧数据兼容与轻量验收

系统 SHALL 保留旧任务 ID、标题、状态、日期、手写上下文、关联和现有修改记录；只读访问不迁移或改写旧文件。保留现有人工编辑版本冲突保护，自动上下文到达不应单独导致人工任务保存冲突。任务/上下文持久化失败不能以“保存成功”反馈。

性能验收使用隔离本地样本：5 个项目，每项目 100 个任务。预热后连续测量 20 次轻量任务读取与普通状态保存，各自 P95 目标不超过 500 ms；测试结果记录机器、样本及实际耗时。该预算是待验证目标，不是当前已达到的声明；AI 总结总耗时不在本次保证范围内。

#### Scenario: A-14 兼容、冲突和速度
- **WHEN** 载入旧任务文件、执行两个真实人工编辑冲突，并在自动端延迟状态下测量上述样本
- **THEN** 原文件只读时字节不变，人工冲突保留当前输入，自动内容更新不造成伪人工冲突；报告功能及实测性能，不以 mock 通过证明无人值守自动生成已完成。

### Requirement: P-10 整站原型对齐不重做进度业务

系统 SHALL 在统一六栏网站壳内使用已确认进度原型的卡片、任务时间条、Done 收起与详情交互；项目首页的进入动作默认打开科研进度，知识库不重复承载继续上次。既有状态、排序、日期和人工内容保护规则 MUST 保持有效，原型中的简化 Todo/Done 演示不能删掉未开始/进行中/卡住状态。

#### Scenario: A-15 继续上次与周切换
- **WHEN** 用户进入项目，在上一周、本周、下一周和次要两周/四周范围间切换，并点击任务或标记完成后重开
- **THEN** 只改变视图而不修改计划日期；继续上次按 P-04 展示；Done 和人工上下文仍持久保存；新建/详情与确认源稿一致。

#### Scenario: A-16 新视觉与旧验收分开
- **WHEN** 执行者交付新进度页面
- **THEN** 同时提供新临时网页对照和原任务数据/非阻塞回归证据，不以已有业务任务勾选证明新页面已经实现，不因改布局重新运行模型。
